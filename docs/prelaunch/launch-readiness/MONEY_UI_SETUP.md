# 小程序本人资金及退款受理入口

首页“收款与退款记录”进入 pages/money-records/index。

正式账号会话验证并初始化 USER 绑定。服务能力关闭时明确不可用，不返回模拟数据。仅服务端按本人归属列出报名，保留已失效报名，20 条分页，展示活动标题、时间及最近一份正式退款申请。不会返回餐厅地址、其他用户、商户号或渠道凭据。

金额入口要求 FEATURE_V11_FINANCIAL_RECORDS=true；退款入口要求 FEATURE_V11_REFUND_INTAKE=true。两者仍要求真实身份 provider、正式身份开关及 demo 关闭。客户端使用原微信会话，不建立第二个凭据缓存。

退款未获得响应时，本地按 userId/registrationId 保存非敏感幂等键；重开页面重试沿用该键。服务端已有最近申请时仅查询该申请，不再次 POST。不同设备在无申请响应且尚未查询到受理结果时，跨设备重复申请尚须后续审核工作流去重，不能据此授权多笔退款。

页面隐藏即清除资金和申请数据；show 重新加载。每个异步响应同时核对页面代次与当前会话，账号变化后清除旧记录。提交和查询按钮在处理中禁用。

验证范围：合成 JWT + owned PostgreSQL 的本人列表/分页/归属；React DOM 原生测试使用 Taro 表面适配和模拟客户端，覆盖金额、申请进度、响应未知后重开复用幂等键、账号变化迟到响应、隐藏清除。不是微信真机验收。

已记录收款与退款不能证明账期完整性、正式政策生效或退款批准。正式报名、wx.requestPayment、运营审核和实际通知仍待完成。

回滚：关闭财务/受理服务开关；恢复 docs/prelaunch/backups/L03-money-ui 内对应文件，移除新增 money-records 页面及 miniapp-money DOM 测试，撤回本人列表装配。保留申请、审计和财务数据，不删除数据库记录。
