# 单日持久化分批比较：实测依据与一致性要求

2026-10-01。待实现设计，不是完成证据、正式政策或上线授权。

当前候选d2b9de60的owned PostgreSQL实测：全部为本应用付款且缺本地intent的合成账单。100、1000、10000条分别564、1880、16962ms提交；30000条只有8198359字节，在30241ms以P2028拒绝，事件/case/快照审计均0。实测脚本及SHA见两个L04_BILL_CAPACITY报告；没有真实商户、资金POST或生产测量。不能由该负载推算正式容量，也不能靠扩充32MiB缓冲或延长事务冒充解决。

下一实现必须覆盖整份账单及双向比较，不以只看渠道行或只有分页输出替代：

1. 任务固定完整绑定、账期、source SHA、owner、release、比较版本及run UUID。旧v3审计不在新任务内重新解释。可信来源仍来自渠道验签/hash链路；私有缓存或本地进度不授予可信性。
2. 持久化输入阶段只保存最小投影与行序/hash，整份UTF8/CSV/header/唯一编号/金额/footer校验通过之前，任何分批记录都不能作为合格渠道观察、case关闭或资金依据。未完成、截断或摘要矛盾明确失败。恢复重验输入身份，不能静默跳过损坏分块。
3. 本地比较依据必须是同一时点的不可变资金快照。可在一个RepeatableRead事务中以数据库集合操作捕获范围内intent、receipt/binding、refund和时间证据的最小投影；不能用多个事务逐页读取活表却声称同一快照。读取复制本身失败不生成有效快照标志。
4. 对完整有效输入与固定本地快照分批比较，页结果、事件/case、query-only任务及进度同事务提交。固定task/page编号幂等；重启只恢复匹配身份和已提交页。不调用支付/退款POST，不改money、成员或资格状态，不把旧case自动关闭。
5. 反向扫描本地收款及可信账期内退款，必须与整份已验证渠道输入anti-join，不能只与当前页比较。未知时间、额外来源、异scope/config、重复序号及事实冲突保留核对状态。
6. 仅所有输入页、正向/反向比较页及总额/计数/摘要守恒一致后提交一次最终审计序号。中途页不得满足range恢复或ready；终态仍需差异闭环、legacy域、真实渠道验收和正式发布范围，不能仅凭零差异宣称COMPLETE。

必要验证：本轮实测负载分批后确实能完成；页边界重复、footer错误、来源/配置变化、途中本地资金变化、正反向缺失、并发同任务、SIGKILL前后提交边界、损坏checkpoint及失败回滚。迁移须有回滚说明；真实数据及新运行配置仍留仓库外。正式实现之前，本轮没有修改源代码、schema或交易限额，最后29步完整工程回归仍只对应原候选。
